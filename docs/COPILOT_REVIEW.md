# Copilotレビューの範囲と回数

## 実行設定

GitHub ruleset `Optional Copilot review`（ID `24004828`）を使う。

| 設定 | 値 |
| --- | --- |
| 対象 | main向けPR |
| Draftのレビュー | 有効 |
| 新しいpushごとのレビュー | 無効 |
| マージ必須条件 | Copilotの完了・承認を追加しない |

レビュー対象の差分がまとまってからDraft PRを作る。プレビューとCIは並行して実行する。レビューを増やすためのPR作り直しや、Ready/Draftの切替、同じSHAへの再依頼はしない。レビュー指示を狭めても、レビューの起動回数や消費そのものをゼロにはできない。

## 作業者が再レビューを依頼する条件

初回レビュー後に次の変更が入り、影響範囲の検証と作業者の確認だけでは具体的なリスクを解消できない場合に限る。

- 保存形式・重要な状態遷移・決済や認証などの重要ロジックを大きく変更した。
- 権限・秘密情報の扱い・公開処理・未信頼コードの実行境界を変更した。
- 指摘された不具合の修正が広範囲に及び、別の退行が懸念される。

再依頼時はPR本文に対象SHA・変更点・確認したいリスクを記録する。通常の指摘修正、文言・整形・文書の調整、同じ結果の再確認だけでは再依頼しない。再依頼しない場合も必要なCIと作業者レビューは省略しない。

## 指摘の扱い

Copilotには `.github/copilot-instructions.md` の観点で具体的な不具合を調べてもらう。指摘が届いたら条件と根拠を確認し、妥当なら修正と必要な回帰テスト、誤検知・重複・承認済みの範囲なら理由をPRへ記録して解決する。内容を読まず自動解決しない。

承認済みの参照リンク公開と画像配布の許可は区別する。PR #9の承認は指定Figmaの参照情報に限定され、他の非公開情報の公開許可ではない。

未契約・残量不足・障害なら追加の利用枠を購入せず、作業者レビューと必須CIで進める。Copilotの指示はベストエフォートであり、不要な指摘が完全になくなる保証はない。

## 設定を変更するとき

指示ファイルはPRで変更し、起動回数はGitHubのrulesetで変更する。両者を混同しない。今後Draftレビューを無効にする場合は、Ready時のレビュー開始と自動マージの関係を確認してから変更する。
