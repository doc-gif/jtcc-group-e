# ピッチ用の実物グッズ写真のアップロード手順（担当者向け）

みんなの開封ルームの結果画面（マスター T10 / 07 / 結果 `267:9379` の「今日のピース」）に、オリジナルの商品イラストの代わりに実物グッズの写真を出すための手順です。写真は **担当者が Supabase の Dashboard から直接アップロード** します。リポジトリ・`public/`・確認用プレビュー・本番のビルドには入れません。

所要時間: 10 分ほど。

## 許諾の範囲（2026-09-26、担当者）

- **ピッチと関係者だけ**に見せる。一般公開のデモ（HANDOFF の 7「デモ用リンク」）には使わない。広げるときは担当者が許諾の範囲を確かめてから、別の作業で有効にする。
- **実物グッズの写真だけ**。キャラクターの絵・世界観のイラスト（W001–W100）はアプリに入れない。
- 写真の下に、素材ライブラリのカードと同じ権利表記を1行出す（アプリが自動で出す）。

## しくみ（知っておくこと）

| 項目 | 内容 |
| --- | --- |
| 置き場所 | Supabase `lastpiece-pitch` の Storage の非公開バケット `pitch-goods`（JPEG だけ・1 枚 1 MiB まで） |
| 見られる人 | **開いているルーム（2 時間の期限内）に参加中の人とそのホストだけ**。ルームを出た人・招待のない人・ログインしていない人・期限が切れたルームの人は読めない（2026-09-26 に実 DB で確認、[記録](SQL_MIGRATION_F15.md)） |
| 書き込み | アプリからはできない（読み取りのポリシーだけ）。Dashboard からだけ |
| 出る場面 | ルームの結果画面で、**自分が当てた品の写真**だけ。ロビー・秒読み・みんなのピースの一覧は今までどおり |
| 写真がないとき | 未アップロード・読めない・壊れた画像のときは、今までのオリジナルの商品イラストのまま（権利表記も出ない）。エラーは出ない |
| 端末内デモ | 開発サーバー・テストの端末内デモでは写真を読まない |

## 1. 写真を用意する（Figma から書き出す）

素材ライブラリ（内部検討用）[限定グッズ棚 `5:2`](https://www.figma.com/design/MYYMoB2wL7LvA2oXZ2gxpT?node-id=5-2) の原画像を使います。賞品とライブラリの対応は `src/app/pitchPhotos.ts` の `PITCH_PHOTOS` と同じです。

| アプリの賞品（光り方） | 素材 | 原画像の node | アップロードする名前 | 画面に出る権利表記 |
| --- | --- | --- | --- | --- |
| マスコット（目玉） | L001 マイメロディ マスコット | [`5:13`](https://www.figma.com/design/MYYMoB2wL7LvA2oXZ2gxpT?node-id=5-13) | `goods/plush.jpg` | 写真: © 2024 SANRIO CO., LTD. TOKYO, JAPAN 著作 株式会社サンリオ |
| ポーチ（キラキラ） | L015 キキ＆ララ50周年 ポーチ | [`5:145`](https://www.figma.com/design/MYYMoB2wL7LvA2oXZ2gxpT?node-id=5-145) | `goods/pouch.jpg` | 写真: © 2025 SANRIO CO., LTD. TOKYO, JAPAN 著作 株式会社サンリオ |
| 缶バッジ枠（ふつう） | L011 メロクロ ガラケー風アクリルチャーム | [`5:105`](https://www.figma.com/design/MYYMoB2wL7LvA2oXZ2gxpT?node-id=5-105) | `goods/badge.jpg` | 写真: © 2024 SANRIO CO., LTD. TOKYO, JAPAN 著作 株式会社サンリオ |

1. 上の node のリンクを開き、原画像（`L001 / 原画像 / …` の四角）だけを選ぶ。カード全体（説明文つき）を選ばない。
2. 右のパネルの「エクスポート」で **JPG**・倍率 **1x** を選んで書き出す。
3. 書き出したファイルの名前を `plush.jpg`・`pouch.jpg`・`badge.jpg` に変える（小文字・拡張子は `.jpg`）。
4. ファイルの大きさが **1 MB 以下**か確かめる。超えたら倍率を 0.5x にして書き出し直す（画面では幅 144px ほどで出るので、長い辺 600px あれば足りる）。
5. このファイルは **リポジトリのフォルダ（`jtcc-group-e` の中）に置かない**。デスクトップなど別の場所に置き、アップロード後に消してよい。

写真を入れ替えたいとき（別の素材を使うなど）は、ファイル名は同じまま中身だけを替えてください。素材と権利表記の組み合わせを変える場合は `PITCH_PHOTOS` の変更が要るので、依頼してください。

## 2. Supabase にアップロードする

1. [Supabase Dashboard の Storage（`lastpiece-pitch`）](https://supabase.com/dashboard/project/vfwlulahhjtuqnrjjohd/storage/buckets) を開き、バケット **`pitch-goods`** を選ぶ。鍵のマーク（非公開）が付いていることを確かめる。**「Make public」にしない。**
2. 「Create folder」で **`goods`** を作り、開く。
3. 「Upload files」で `plush.jpg`・`pouch.jpg`・`badge.jpg` をアップロードする。
4. 一覧に `goods/plush.jpg`・`goods/pouch.jpg`・`goods/badge.jpg` の3つが並ぶことを確かめる。JPEG 以外や 1 MB を超えるファイルはバケットの設定で断られる。

「Get URL」「Copy URL」で作る署名付き URL は、ルームの外の人でも期限まで開けてしまいます。**作らない・人に送らない**でください（アプリは本人のログインで読むので不要です）。

## 3. 本番で確かめる（スマホ3台）

1. ホスト用リンク（担当者だけが持つ `host-key.md` のリンク）でルームを作り、ほかの2台で招待リンクから入る（開始にはホストのほかに2人以上が必要）。
2. ホストの「開始の時間を予約する」で **ピッチ用** をオンにし、1分後に予約する（ピッチ用はラウンドごとに1人に目玉＝マスコットが確定するので、`plush.jpg` を確かめやすい）。
3. 開封のあと「結果を見る」→ 各端末の「今日のピース」に、**その人が当てた品の写真**と、下に権利表記の1行が出ることを確かめる。
4. 写真が出ずにイラストのままなら、ファイル名（`goods/` の下・小文字・`.jpg`）と、その端末がルームに入っているか（ルームを出た後・期限切れの後は出ない）を確かめる。

## 4. ピッチが終わったら

- 許諾はピッチと関係者だけなので、使い終わったら `pitch-goods` の3つのファイルを Dashboard で選んで **Delete** する。消すとアプリは自動でイラストに戻る（コードの変更・公開は要らない）。
- 次のピッチで使うときは、2 からやり直す。

## やらないこと

- バケットを公開にする・ポリシーを足す（読み取りの条件は migration `20260926052120_lp_pitch_goods_photos` で決めている。変えるときは新しい migration と `lock:supabase` の宣言が要る）。
- 写真を GitHub・PR・Issue・チャット・`public/`・確認用プレビューに置く。
- キャラクターの絵や世界観のイラストをアップロードする。
