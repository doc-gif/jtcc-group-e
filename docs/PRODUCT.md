# プロダクトメモ

## アプリ：ラストピース（提案モック）

日本トレカセンター（JTCC）インターンのビジネスコンテスト「女性市場を開拓せよ」の提出物「02 動くモック」。

- **一文:** 即完売で買えなかった限定グッズを JTCC が買い取り・検品し、確率を公開したオリジナルガチャとして届ける。コレクションに足りない「最後の一点」を、友達といっしょに引き当てる。
- **誰に:** 推しが決まっていて、限定品を買えなかった経験がある 20〜30 代の女性（サンリオ・すみっコぐらし・ハイキュー!!・ちいかわのグッズ好き）。
- **体験の中心:** 一人で回さず、**リンクで友達を呼び、同じルームで同時に開ける**（共有ルーム。上限は画面に出さない）。当たりも、その場でいっしょに見る。
- **ビジネスモデル:** JTCC 型（B2C）。JTCC が仕入れ・検品した在庫を、確率を公開したガチャで販売する。C2C ではない。

画面の設計は、チーム内の設計書「ラストピース アプリ UI 設計書（2026-09-25）」と、その試作（回す画面の試作5・画面設計 2/4 改訂）を移植したもの。

## 共有ルーム（決定済み・2026-09-26、F07・F10・F13）

提案の場で使う共有ルーム（[契約](SHARED_OPENING_CONTRACT.md)）の決定。画面は Figma の後に実装する（今は状態層と SQL だけ）。

| 項目 | 決定 |
| --- | --- |
| 人数 | ホストを含め最大 100 人（内部の上限）。画面には上限を出さず「N人が集まっています」だけを出す |
| 架空在庫 | 新しいルームは 300 個（目玉 30・ポーチ 90・缶バッジ 180。以前の 100 個と同じ比率で 3 倍） |
| 予約開始 | ホストが「1 / 3 / 5 / 10 分後に開始」を選ぶ。全員に開始時刻と秒読みを出す。開始前ならホストは変更・取り消しでき、「今すぐ開始」も使える。時刻になると、ホストが不在でもサーバーが開始する（その時点でオンラインの準備OKの人が対象）。予約はルームの期限（作成から 2 時間）の 1 分前まで。誰も準備していなかったなどで始まらなかったときは、ホストにその理由を出す |
| ピッチモード（ホストモード） | 対面のビジネスピッチで会場が反応できるよう、ホストがルームごとにオンにする。オンの間、各ラウンドで参加者 1 人に目玉を確定する（本物の在庫から出す）。全員の画面に「ピッチ用デモ：このラウンドは1人に目玉確定」などと明示する。目玉の在庫が 0 なら装わず、通常の抽選にして「確定なし」と分かるようにする |
| 確率の表示 | ピッチモード中は、公開している確率は確定枠には当てはまらない（確定枠以外の人には当てはまる）。画面はそのことを確率の近くに表示する |
| ホスト（F10） | ホストになれるのは担当者だけ。リンクは2種類で、参加者に配る招待リンクと、担当者だけが持つホスト用リンク（秘密のキー入り）。ホスト用リンクでだけルームを作れ、別の端末で開けばホストに戻れる（ほかの人の席・コイン・結果はそのまま）。参加者がホストを代わることはない（旧仕様の「ホスト交代」は廃止）。ホストがいなくても予約した開始は時刻に始まる。無効なリンクは「ホスト用リンクが無効」と案内し、ルームは作らない |
| 名前（F10） | 1〜12文字。ルームの中で重ならない（全角・半角、大文字・小文字、空白の違いは同じ名前とみなす）。名前を選ばずに入ると「ゲスト さくら12」のような名前が付き、入る前に見せる。使われている名前には「「もも2」で入る」のように空いている候補を出す。ロビーで名前を変えられる |
| 開始の人数（F13） | 担当者の決定（2026-09-26「ガチャはホスト以外に2人以上じゃないと引けないようにしたい」）。ルームのラウンドは、ホストのほかに退室していない参加者が2人以上（ホストを含めて3人以上）いるときだけ始められる。足りないと「今すぐ開始」は押せず「あと N 人で始められます」と出す（参加者の画面にも同じ案内）。予約は人数が足りなくてもでき、時刻を過ぎても足りなければ始めずに待ち、2人目が入った時点で始まる（ホストは待っている予約を変更・取り消しできる）。ピッチモードも同じ。人数は「集まっている人 N人」だけを出し、上限は出さない。ひとりで回すガチャと「友達と回す（デモ）」（本人と友だち2人）は変わらない |

「確定演出は本当に目玉が出るときだけ」は変わらない。確定枠の目玉は実際に出る。

## 守ること（法務・ブランド）と、効かせ方

`scripts/governance.test.mjs`（`pnpm test` で実行・CI で落ちる）と、`src/domain/domain.test.ts` で確認する。

- 禁止語（換金・必ず当たる・還元率100%・大当たり・中当たり）を画面の文言に使わない。
- 「提案モック・公式サービスではありません」を各画面に出す。
- ピピのセリフ（`src/copy/pipi.ts`）に実在キャラクターの名前を入れない。
- 公開する画像はオリジナル素材の置き場所だけ（許可リスト）。サンリオ等の公式画像・ロゴ・キャラクター絵は使わない。キャラクター名は取り扱い商品の事実としてテキストだけ。
- 交換率は一律 20%。交換シートに「出金できません」「取り消せません」を出す。
- ガチャ詳細に残り口数の数字を出さない。確率の合計は 100%、残り 0 は 0%。
- 確定演出は目玉のときだけ（`shouldShowKakutei`）。
- 発売から 90 日以内の商品はカタログに入れない（`releasedAt` をテスト）。
- 友達へのコイン送付、賭け・勝ち負けの表示、「売る」機能は作らない。

## 読み込み中（T07 Loading `267:8244`、F09）

- 街を出す前に待つのは、上部のコイン・マイページのアイコンと注目のピースの絵、使っている文字（フォント）だけ。街の地図はアプリに組み込んだ SVG なので待たない。読み込みはアプリを開いた直後に、どの画面から開いても始める。
- 待ちが 0.3 秒（`LOADING_DELAY`）続いたときだけ読み込み中を出す。それより早く準備できたら出さない（ちらつき防止）。わざと待たせる最低表示時間はない。導入のあとは、猶予のあいだ導入を出したままにする。
- 読み込み中は動きのない1枚。見出し「街の準備をしています」と文で状態を伝え、進み具合の数字は出さない（本当の割合が分からないため）。準備できたら自動で街へ進む。「スキップ」「街を見る」で先に街へ行ける（絵はあとから出る）。
- 読み込めなかったら「街の準備ができませんでした」と伝え、「もう一度読み込む」でやり直せる。先に街へも行ける。
