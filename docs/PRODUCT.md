# プロダクトメモ

## アプリ：ラストピース（提案モック）

日本トレカセンター（JTCC）インターンのビジネスコンテスト「女性市場を開拓せよ」の提出物「02 動くモック」。

- **一文:** 即完売で買えなかった限定グッズを JTCC が買い取り・検品し、確率を公開したオリジナルガチャとして届ける。コレクションに足りない「最後の一点」を、友達といっしょに引き当てる。
- **誰に:** 推しが決まっていて、限定品を買えなかった経験がある 20〜30 代の女性（サンリオ・すみっコぐらし・ハイキュー!!・ちいかわのグッズ好き）。
- **体験の中心:** 一人で回さず、**リンクで友達を呼び、同じルームで回す**（最大4人）。当たりもおそろいも、その場でいっしょに見る。
- **ビジネスモデル:** JTCC 型（B2C）。JTCC が仕入れ・検品した在庫を、確率を公開したガチャで販売する。C2C ではない。

画面の設計は、チーム内の設計書「ラストピース アプリ UI 設計書（2026-09-25）」と、その試作（回す画面の試作5・画面設計 2/4 改訂）を移植したもの。

## 決まっていること

| 項目 | 決定 |
| --- | --- |
| 基盤 | React + Vite のスマホ向け Web アプリ（このリポジトリの基盤に合わせる） |
| 呼び方 | 「パック」ではなく「ガチャ」 |
| 作品（上のカード） | サンリオ／すみっコぐらし／ハイキュー!!／ちいかわ |
| グッズの種類（タブ） | すべて・ぬいぐるみ・アパレル・バッグ・アクセサリー・文房具・缶バッジ/アクスタ |
| 並び替え | おすすめ順／即完売品／残りわずか／新入荷 |
| 等級 | 画面に等級の文字（大当たり・中当たり等）は出さない。光り方で見分ける（目玉＝ローズゴールド、キラキラ＝パール）。詳細画面の「✦ 目玉」の見出しだけ使う。読み上げ用に隠し文字で区分を伝える |
| 確率 | 常に公開。**いまの残りから計算した値**を中身ごとに出す |
| 残り | **残り口数の数字（◯/◯）は出さない。** 数字なしの残りバーと言葉（たっぷり／半分くらい／残りわずか／売り切れ）を、ホームのカードとガチャ詳細の両方に出す |
| 回し方 | 1回ずつ。ハンドルを指で時計回りに **3回転**（回しにくい人向けに「1タップで1回転」ボタン）。連続で回す機能は作らない |
| 演出 | 1回転ごとに筐体と背景が豪華になる。**確定演出は本当に目玉が出るときだけ**（ガセ演出はしない） |
| 開封 | カプセルをタップで開ける（ほか1回／キラキラ2回／目玉3回）。「使ったコイン → 当たった物 ¥◯◯相当」を出す |
| 友達と回す | ルームは最大4人。リンクを受け取った人だけが入れる（公開の募集はしない）。みんなの結果・おそろい・スタンプ・「いいな〜」 |
| コイン | **1コイン＝1円**。購入はデモ（押すと増えるだけ。決済は作らない）。はじめての人には体験用 3,000 コイン |
| 当てたもの | 倉庫ではなく記録。1つずつ「届けてもらう」か「コインに交換」 |
| コインに交換 | **参考価格の一律 20%**（端数切り捨て）。出金不可・取り消し不可。画面では「換金」と言わない |
| 案内役 | オリジナルキャラクター「ピピ」。実在キャラクターにはしゃべらせない |
| 見た目 | 配色「さくらミルク」（白〜パステルピンク）。演出時だけローズゴールドとパール。確定時はワインローズ。ロゴはリボン案 |
| 画像 | `public/assets/` のオリジナル生成素材だけを使う（ロゴ・作品・種類・UIアイコン・商品イラスト・バナー） |
| 声と音 | ピピの読み上げとチャイム・振動は、マイページで ON にしたときだけ鳴らす（最初は OFF） |
| 保存 | この端末の localStorage（キー `lastpiece_app_v1`）。壊れたデータは最初の状態に戻す。保存できない端末ではその旨を表示。F04 でお気に入りと「いいな〜」を追加（前の保存データは空として読む） |
| 棚（F04） | 9枠。いま持っている品（手元にある・届け待ち）を種類ごとに1枠で、お気に入り（付けた順）→ 先に当てた順に並べる。10種類目からは棚の外（当てたもの一覧で見られる）。コインに交換した品は外れる。空き枠は点線の丸と「未入手」の文字 |
| お気に入り（F04） | 持っている品に付け、いつでも外せる。付けた品は棚の前に並ぶ |
| フレンド（F04） | いっしょに回した友だち（デモのゆい・さき）だけが出る。ゆいの棚は固定のデモデータ、さきは「今は見られません」の状態見本。友だちの品は自分の持ち物に入らない |
| 共有（F04） | 「友だちからの見え方」は確認だけで、どこにも公開しない（「共有はまだ実行していません」）。見えるのはプレビューに出る棚の9枠だけ |
| 表示 | すべての入口に「提案モック・公式サービスではありません」と、商品・価格・在庫・確率が説明用の架空データである注記 |

## 守ること（法務・ブランド）と、効かせ方

`scripts/governance.test.mjs`（`pnpm test` で実行・CI で落ちる）と、`src/domain/domain.test.ts` で確認する。

- 禁止語（換金・必ず当たる・還元率100%・大当たり・中当たり）を画面の文言に使わない。
- 「提案モック・公式サービスではありません」を各画面に出す。
- ピピのセリフ（`src/copy/pipi.ts`）に実在キャラクターの名前を入れない。
- 公開する画像はオリジナル素材の置き場所だけ（許可リスト）。サンリオ等の公式画像・ロゴ・キャラクター絵は使わない。キャラクター名は取り扱い商品の事実としてテキストだけ。
- 交換率は一律 20%。交換シートに「出金できません」「取り消せません」を出す。
- ガチャ詳細に残り口数の数字を出さない。確率の合計は 100%、残り 0 は 0%。
- 確定演出は目玉のときだけ（`shouldShowKakutei`）。
- 発売から 90 日以内の商品はカタログに入れない（`releasedAt` をテスト）。
- 友達へのコイン送付、賭け・勝ち負けの表示、「売る」機能は作らない。

## 画面（ハッシュで表す。固定版 URL でも再読み込みできる）

| URL | 画面 |
| --- | --- |
| `#/` | 街（ホーム）。URL にハッシュがない状態で開いたときだけ導入（約3秒・スキップ可、動きを減らす設定では1枚で自動では進まない）を出し、終わると `#/` に置き換える |
| `#/gacha` | ガチャのお店（ガチャ一覧） |
| `#/welcome` | はじめて（説明・ニックネーム・ホーム画面への追加の案内） |
| `#/gacha/<id>` | ガチャ詳細（中身の全リスト・確率・残りバー・お知らせ・注意事項） |
| `#/gacha/<id>/room` | ルームを作る（招待リンク・待ち合わせ） |
| `#/gacha/<id>/spin` | ひとりで回す |
| `#/room/<code>` | 招待リンクの行き先（招待状 → ニックネーム → 待ち合わせ） |
| `#/room/<code>/spin` | みんなで回す → みんなの結果 |
| `#/together` | フレンド（いっしょに回した友だち（デモ）の棚への入口）。ルームはガチャ詳細の「友達と回す」から作る |
| `#/friend/<id>` | 友だち（デモ）の棚。見られない友だちは理由と戻り先を出す |
| `#/friend/<id>/<品のid>` | 友だちの1点と「いいな〜」（デモ・同じ品に1回だけ） |
| `#/shelf` | わたしの棚（9枠） |
| `#/shelf/<品のid>` | わたしの1点（お気に入りを付ける・外す） |
| `#/shelf/share` | 友だちからの見え方（共有前のプレビュー。公開はしない） |
| `#/collection` | 当てたもの（合計・絞り込み・コインに交換・届けてもらう。棚の何番目かも出す。棚の「一覧」から来る） |
| `#/me` | マイページ（コイン・ニックネーム・声と音・お知らせ・きまり・デモ操作） |

下のタブはデザインマスターに合わせて **街・ガチャ・コレクション・フレンド** の4つ（F02）。コレクション → `#/shelf`（わたしの棚）、フレンド → `#/together`（フレンド）へつなぐ（F04）。街の地図の「コレクション」も棚へ行く。マイページはタブにせず、上部のコイン残高とアイコンから開く。

街の地図はマスターの部品（`267:10063`）のオリジナルのベクター画をコードの SVG で描き直したもの。マスター中央の内部キャラクター参照は案内役ピピに、注目のピースの商品写真は `public/assets/goods/` のオリジナルの商品イラストに置き換えた（内部素材は使わない）。地図の「当てたもの N」は、この端末の記録の数（マスターの「棚 2/9」はデモ例のため出さない）。

## デモであること（実在のデータや動作を装わない）

- 友達（ゆい・さき）の入室・回転・結果は、この端末の中で再現している。画面に「デモ」と明記する。別のスマホとはまだつながらない。
- フレンドの棚（ゆい）・「今は見られません」（さき）・「いいな〜」はデモ。「いいな〜」はこの端末に記録するだけで、相手には届かない。棚の共有（公開）はしない。
- カタログ（4作品 × 3本 = 12本）・参考価格・在庫はすべて説明用の架空データ。
- コインの購入・発送はしない。「届けてもらう」は状態を「届け待ち」にするだけ。
- マイページの「次の1回を目玉確定にする」は審査用のデモ操作（1回で解除）。

## 設計書との違い（このリポジトリで判断したこと）

- 設計書は Next.js（`lastpiece-app/`）を想定していたが、このリポジトリの基盤（React + Vite・GitHub Pages）に合わせた。
- 画面の URL はハッシュ（`#/...`）にした。静的ホスティングの固定版 URL でも再読み込みできるようにするため。
- ホームのカードの「♡ ◯ルームで回してる」は出していない。実際のルーム数がないため（数字を装わない）。
- カタログは 1本あたり 8〜12種（設計書は 12〜24種）。

## チームの基盤ルール（main で決まっていること）

- React + Vite を基本とし、スマートフォンで利用する Web アプリを想定する。AI を活用して継続的に開発する。
- 本番の GitHub Pages は明示指示時のみ公開し、各バージョンを固定 URL と Release で残す。確認用サイトは [自動プレビュー](PREVIEW.md) として別途配布する。
- PR ベースで開発し、機能テストと UI/UX 基準の成功を自動承認・マージの条件にする。
- Apple HIG の Web に適用できる原則と、キャラクター／女性向けゲームの設計事例を UI/UX 基準に使う。
- デザインは指定 Figma ファイルで管理する。ラストピースの画面は、担当者の指示（2026-09-26）によりピンク基調の「さくらミルク」を正とし、[デザインマスター](ADOPTED_DESIGN.md)にまとめた。JTCC App 初版の緑系（`docs/DESIGN.md`）は雛形の記録で、ラストピースの主操作には使わない。

## 次の機能を決めるときのテンプレート

### 課題

誰が、どの場面で、何に困っているか。

### 利用者の操作

開始から完了までの操作を短く書く。

### 受け入れ条件

- 利用者が確認できる結果を列挙する。
- エラー時や空状態の表示も定義する。

### 決定事項と保留事項

決めた理由と、後で判断する項目を記録する。
