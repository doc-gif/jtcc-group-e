# I149 限定公開アプリのキャラクターの取得部品・フォールバック・成果物の検査

## 成果
#144 の案 D（非公開バケット + RLS、実行時に本人のログインで読む）のアプリ側の土台。夜間モードで案 D を前提に進めた（担当者の確認は #144）。

- `src/realtime/characters.ts`: 非公開バケット `pitch-characters` から本人のセッションで読む取得元。写真（F15）と共通の `privateImageSource(client, bucket)` を `photos.ts` に作った。セッションが無ければ読まない（キャラクターのためだけに匿名ログインしない）。
- `src/app/sharedRoom.ts`: `RoomSession.characters`（端末内の模擬ルームでは null）。
- `src/app/pitchCharacters.ts`: `CHARACTER_SLOTS`（7 か所 → `chars/*.png`）、`CharacterProvider`（ルームの記録かホスト用キーがあるときだけ 7 枚を並列に 1 回、ルームに入ったときに読めなかった分を 1 回だけ取り直す。メモリの object URL だけ、外れるとき・退室や期限切れでルームに関わらなくなったときに取り消す）、`useCharacter(slot)`。`App.tsx` に Provider を置いた。
- `src/components/CharacterArt.tsx`: 絵が無い・表示できないときは null。あれば飾りの `<img>`（`alt=""`・`aria-hidden`・`position: absolute`・`pointer-events: none`・0.2 秒のフェード、動きを減らす設定では無し）。画面への配置はまだ（#146）。
- `scripts/check-dist.mjs`: `pnpm build` の最後に、`dist/` の画像が `public/` と同じものだけ、テキストに内部素材の ID・Figma の URL・公開 URL と署名付き URL（の作成の呼び出し）・2 KB 以上の `data:image/` が無いことを検査する。
- `scripts/governance.test.mjs`: `public/` に `chars/` を置かない、`src/` で `createSignedUrl`・`getPublicUrl` を使わない、`build` が検査を走らせる。
- 文書: `docs/PITCH_CHARACTERS.md`（担当者の手順）、`docs/ASSET_LIBRARY.md` の例外、`docs/PRODUCT.md` に 1 段落。

## 検証と証拠
- 単体テスト: `src/realtime/characters.test.ts`・`src/app/pitchCharacters.test.tsx`（`new Blob` の無地のダミー PNG）・`scripts/check-dist.test.mjs`（仮の `dist/` に許可外の画像・素材 ID・署名付き URL・大きな data URI を入れて失敗、正常で成功）。
- `pnpm verify` と必須 CI は PR（#149 を閉じる PR）の記録を見る。

## 残課題
- 画面への配置（#146）、バケットと RLS の migration の適用（#150）。
- 設計どおりの「成果物に `createSignedUrl`・`getPublicUrl` が無い」は、`@supabase/supabase-js` がこの名前のメソッドを定義しているため名前では検査できない。呼び出し（`.createSignedUrl(`・`.getPublicUrl(`）と Storage の公開・署名付き URL のパスで検査し、アプリのコード（`src/`）は名前そのものを governance で禁止した。
